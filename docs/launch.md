# Запуск магазину

<p class="lede">Коротка перевірка перед тим, як пускати реальних покупців. Пройдіть її повністю — це дешевше, ніж розбиратися з проблемою на живому трафіку.</p>

---

## Мінімальний шлях до першого продажу

<div class="steps" markdown>

**1.** Створіть магазин (`🛍️ Створити мій магазин` у боті Cartium), відкрийте бота магазину і виконайте `/admin`.

**2.** Якщо система просить — прийміть політику конфіденційності та правила використання.

**3.** Переконайтеся, що бачите розділи `📦 Товари`, `📂 Категорії`, `📋 Замовлення`, `⚙️ Налаштування`.

**4.** Створіть категорії, потім додайте товари з фото, цінами і варіантами.

**5.** Увімкніть хоча б один робочий спосіб оплати.

**6.** Якщо плануєте доставку Новою поштою — збережіть API ключ і дані відправника.

**7.** Перевірте вигляд магазину і тексти кнопок.

**8.** Пройдіть повний тестовий сценарій як покупець.

**9.** Оберіть тариф у `Налаштування` → `Підписка` до завершення пробного періоду (14 днів).

</div>

## Чекліст

### Доступ

- [ ] `/admin` відкриває меню
- [ ] Усі, кому потрібен доступ, додані в `Налаштування` → `Команда`

Якщо доступу немає — виконайте `/myid` і передайте свій числовий Telegram ID власнику магазину.

### Каталог

- [ ] Категорії створені
- [ ] Товари активні — стоїть галочка `Активний у каталозі`
- [ ] У кожного товару є хоча б одне фото
- [ ] Ціни коректні
- [ ] Розміри й кольори заведені **варіантами**, а не текстом в описі
- [ ] Режим залишків обраний свідомо для кожного товару
- [ ] Для товарів із відстеженням залишків є варіанти з ненульовим залишком

### Оплати

- [ ] Увімкнений хоча б один спосіб оплати
- [ ] Для товарів у режимі `Без ліміту залишку` є хоча б одна онлайн-оплата
- [ ] Якщо використовуєте LiqPay — збережені **бойові** `Public key` і `Private key` (не `sandbox_…`) і компанію активовано
- [ ] Якщо використовуєте Monobank — збережений бойовий `Merchant Token`
- [ ] Натиснута кнопка `Зберегти зміни`, статус способу — `Активний`

### Доставка

- [ ] API ключ Нової пошти збережений
- [ ] Місто і точка відправлення вибрані **зі списків пошуку**
- [ ] Заповнені `ПІБ відправника` і `Телефон відправника`
- [ ] Натиснута кнопка `Зберегти доставку`, API ключ не прострочений

### Вигляд і тексти

- [ ] Логотип і банер завантажені
- [ ] Шаблон, тема й акцентний колір обрані
- [ ] Тексти магазину перевірені
- [ ] Назви кнопок зрозумілі покупцю

### Підписка

- [ ] Підписка активна або пробний період ще триває
- [ ] Режим доступу магазину — `За статусом підписки` або `Працює у звичайному режимі`

## Тестовий сценарій

Обовʼязково пройдіть повний ланцюжок **власноруч**, перед першим реальним трафіком.

!!! tip "Підготуйте тестовий товар"
    Заведіть окремий товар з мінімальною ціною — наприклад, 1 грн. Так ви пройдете реальну оплату, не витрачаючи грошей. Після перевірки просто зніміть галочку `Активний у каталозі`.

1. Відкрийте магазин як покупець — з іншого акаунту або через звичайне меню бота.
2. Перейдіть у каталог і знайдіть товар.
3. Додайте його в кошик.
4. Пройдіть оформлення до кінця.
5. Завершіть оплату: для LiqPay на тестових ключах — тестовою карткою, в усіх інших випадках — реальною карткою на мінімальну суму.
6. Перевірте, що замовлення зʼявилося у вас в адмінці.
7. Перевірте, що статус коректний — для LiqPay і `plata by mono` має стати `Оплачено` автоматично.
8. Якщо використовується доставка — переконайтеся, що кнопка `Створити ТТН` доступна і ТТН створюється без помилки.

## Не запускайте магазин, якщо

!!! warning "Стоп-список"
    - немає жодного перевіреного способу оплати;
    - не пройдений хоча б один тестовий checkout від початку до кінця;
    - товари не мають фото або ціни;
    - не перевірені тексти й кнопки;
    - для Нової пошти не внесені дані відправника;
    - магазин працює на тестових ключах `sandbox_…`;
    - ви не знаєте, що робити із замовленням у статусі `Оплата на перевірці`.

Кожен із цих пунктів на живому трафіку перетворюється на втраченого покупця, який більше не повернеться.

## Перший тиждень після запуску

Магазин запущений — далі важлива дисципліна, а не нові функції.

| Що робити | Як часто |
|---|---|
| Перевіряти фільтри `Очікують` і `На перевірці` | Двічі на день |
| Підтверджувати оплати й відправляти замовлення | Того ж дня |
| Перевіряти, чи не закінчилися залишки популярних товарів | Раз на день |
| Дивитися `Аналітика` → `7 днів` | Раз на тиждень |

Модулі зростання — промокоди, кампанії, крос-продажі — вмикайте не раніше, ніж базовий цикл почне працювати без вашого ручного втручання.
