# Інструкція для власника

<p class="lede">Цей гайд проведе вас від першого входу в адмінку до стабільно працюючого магазину. Кожен розділ — окрема задача, яку можна закрити за один підхід.</p>

!!! tip "Якщо ви тут вперше"
    Не читайте все підряд. Пройдіть [Швидкий старт](#швидкий-старт) — цього достатньо, щоб прийняти перше замовлення. Решту розділів відкривайте тоді, коли дійде черга.

---

## Швидкий старт

Дев'ять кроків до першого продажу. Робіть їх саме в цьому порядку — кожен наступний спирається на попередній.

<div class="steps" markdown>

**1. Зайдіть в адмінку.** Відкрийте свого бота в Telegram і надішліть команду `/admin`.

**2. Прийміть документи.** Якщо бот попросить — натисніть `✅ Приймаю` для політики конфіденційності та правил використання. Без цього адмін-меню не відкриється.

**3. Перевірте доступ.** Ви маєте побачити меню з розділами `📦 Товари`, `📂 Категорії`, `📋 Замовлення`, `⚙️ Налаштування`. Якщо замість меню бачите «Немає доступу» — [ось що робити](#часті-ситуації).

**4. Створіть категорії.** Спочатку категорії, потім товари. Інакше доведеться перекладати товари руками.

**5. Додайте товари.** Назва, ціна, фото, категорія. Якщо у товару є розміри чи кольори — заводьте їх варіантами, а не текстом в описі.

**6. Підключіть оплату.** Достатньо одного робочого способу. Деталі — на сторінці [Оплати](payments.md).

**7. Налаштуйте доставку.** Якщо працюєте з Новою поштою — внесіть API ключ і дані відправника. Деталі — [Нова пошта](nova-poshta.md).

**8. Перевірте вигляд і тексти.** Логотип, банер, кольори, назви кнопок.

**9. Пройдіть тестове замовлення повністю.** Як покупець: каталог → кошик → оформлення → оплата → замовлення прийшло вам в адмінку → доставка.

</div>

<div class="shot" markdown>
**Скріншот:** адмін-меню бота одразу після команди `/admin` — видно всі шість кнопок розділів.
`assets/shots/admin-menu.png`
</div>

!!! warning "Не починайте з модулів росту"
    Промокоди, кампанії, аналітика і крос-продажі не врятують магазин, у якому не працює базове. Спочатку доведіть до кінця ланцюжок:

    `товар → кошик → оформлення → оплата → замовлення → відправка`

    І тільки потім вмикайте решту.

## Два інтерфейси магазину

### Telegram-бот

Бот — це швидкі дії. Відкрили, зробили одну справу, закрили.

Після `/admin` ви бачите меню:

| Кнопка | Для чого |
|---|---|
| `📦 Товари` | Список товарів, додати або відредагувати |
| `📂 Категорії` | Створити категорії та підкатегорії, змінити порядок |
| `📋 Замовлення` | Нові замовлення, підтвердження оплат, ТТН |
| `📊 Статистика —✨Pro` | Показники магазину з експортом у CSV та Excel |

## Команди бота

Більшість власників знають тільки `/admin`. Насправді команд більше, і деякі економлять час.

### Ваші робочі команди

| Команда | Що робить |
|---|---|
| `/admin` | Відкриває адмін-меню |
| `/orders` | Одразу список замовлень, без заходу в меню |
| `/order` | Картка конкретного замовлення |
| `/markpaid` | Позначити замовлення оплаченим |
| `/addproduct` | Швидко додати товар |
| `/guide` | Інтерактивна інструкція просто в боті |
| `/myid` | Показує ваш числовий Telegram ID |

### Команди, які бачить покупець

`/start`, `/catalog`, `/cart`, `/myorders`, `/cancel`, `/skip`

Варто знати їх, щоб розуміти, що саме описує клієнт у зверненні до підтримки.

!!! tip "Якщо застрягли посеред сценарію"
    Бот веде вас покроково — наприклад, при додаванні товару. Якщо передумали, надішліть `/cancel`. Якщо крок необовʼязковий і хочете його пропустити — `/skip`.

## Хто за що відповідає

### Ви як власник магазину

Все, що стосується щоденної роботи:

| Зона | Що саме |
|---|---|
| Каталог | Категорії, товари, фото, варіанти, залишки, активність |
| Замовлення | Перегляд, підтвердження оплат, відправки, статуси |
| Оплати | LiqPay, Monobank, за посиланням, за реквізитами, накладений платіж |
| Доставка | Нова пошта, дані відправника, ТТН |
| Контент | Тексти магазину, назви кнопок |
| Вигляд | Тема, кольори, шрифти, логотип, банер |
| Зростання | Промокоди, кампанії, аналітика, крос-продажі, сегменти |
| Команда | Адміни магазину, підписка, режим доступу |

### Платформний адміністратор

Потрібен тільки тоді, коли проблема не вирішується з вашої адмінки:

- бот зовсім не відповідає;
- магазин не відкривається;
- проблема з доступом на рівні платформи;
- потрібні технічні зміни поза інтерфейсом магазину.

!!! info "Коли писати платформному адміну"
    Якщо ви можете зайти в `/admin` і бачите меню — швидше за все, питання вирішується налаштуваннями, і цей гайд допоможе. Пишіть платформному адміну, коли не працює сам вхід.

## Каталог

### Де зручніше працювати

**У боті:** `/admin` → `📦 Товари` або `📂 Категорії` — коли треба швидко щось поправити.

**У WebApp:** `Керування` → `Товари` — коли працюєте системно. Там є пошук, список, швидке редагування і повна форма створення.

### Спочатку категорії

Створіть структуру категорій до того, як заводити товари. Підтримуються підкатегорії — в боті можна змінювати порядок кнопками `⬆️ Підняти` і `⬇️ Опустити`.

Це не косметика: від структури категорій залежить, чи знайде покупець потрібне за два дотики, чи гортатиме стрічку з сотні позицій.

### Форма товару

| Поле | Коментар |
|---|---|
| Назва | Те, що покупець бачить першим |
| Опис | Не пишіть сюди розміри й кольори — для цього є варіанти |
| Ціна, грн | — |
| Категорія | Обовʼязково, інакше товар важко знайти |
| Фото | До **5 штук** на товар |
| Режим залишків | `Відстежувати залишки` або `Без ліміту залишку` |
| Назва опції | Наприклад, `Розмір`, `Колір`, `Вага` |
| Варіанти | Конкретні значення опції з власними залишками |
| `Активний у каталозі` | Знімайте галочку, щоб тимчасово прибрати товар з вітрини |

<div class="shot" markdown>
**Скріншот:** форма створення товару у WebApp з заповненими полями і кількома фото.
`assets/shots/product-form.png`
</div>

### Фото

Один товар — до п'яти фото. Практичне правило:

- **перше фото — головне.** Саме воно тягне на себе увагу в стрічці каталогу;
- решта — деталі, кольори, фактура, масштаб;
- якщо ліміт вичерпано, спочатку видаліть зайве, потім додавайте нове.

### Варіанти і залишки

Якщо товар має розміри, кольори чи об'єми — заводьте варіанти. Тоді покупець обирає значення у зрозумілому селекторі, а ви бачите залишки по кожній позиції окремо.

Система оперує двома поняттями:

- **`stock`** — фактичний доступний залишок;
- **`reserved`** — тимчасовий резерв під замовлення, які ще не завершені.

### Режими залишків

| Режим | Що означає |
|---|---|
| `Відстежувати залишки` | Ви задаєте реальну кількість, система її списує |
| `Без ліміту залишку` | Жорсткий облік не ведеться, товар іде під замовлення |

!!! warning "Важливе правило для товарів без ліміту залишку"
    Якщо товар продається в режимі `Без ліміту залишку`, для нього має бути увімкнена **хоча б одна онлайн-оплата**: `LiqPay`, `plata by mono`, `Оплата за посиланням` або `Оплата за реквізитами`.

    Якщо залишити тільки накладений платіж, оформлення такого товару буде заблоковане — покупець просто не зможе його купити.

### Імпорт каталогу

Вкладка `Імпорт` доступна, якщо модуль імпорту увімкнений. Там можна:

- надіслати собі приклад CSV у Telegram;
- надіслати собі приклад XLSX у Telegram;
- завантажити свій файл CSV або XLSX;
- отримати звіт про те, що імпортувалося.

!!! tip "Безпечний спосіб імпорту"
    Не заливайте одразу весь каталог. Візьміть файл на 5–10 позицій, імпортуйте, а потім відкрийте кілька товарів руками і перевірте: назва, ціна, категорія, фото, режим залишків. Якщо все правильно — заливайте решту.

## Замовлення

### Де працювати

**У боті:** `/admin` → `📋 Замовлення` або одразу командою `/orders`. Для більшості оперативних дій бот залишається основною точкою входу.

**У WebApp:** вкладка `Замовлення` — розширений інтерфейс, зручніший для розбору великої кількості.

### Фільтри

| Фільтр | Кого показує |
|---|---|
| `⏳ Очікують` | Замовлення, де ще немає підтвердженої оплати |
| `🧾 На перевірці` | Клієнт натиснув «Я оплатив», потрібна ваша перевірка |
| `📦 До відправки` | Оплачені або накладені, готові до відправлення |
| `🚚 У дорозі` | Уже відправлені |
| `✅ Завершені` | Закриті замовлення |
| `📋 Усі` | Повний список |
| `🔎 Пошук` | Пошук за номером або клієнтом |

### Статуси: онлайн-оплата

| Статус | Що означає | Ваша дія |
|---|---|---|
| `⏳ Очікує оплати` | Замовлення створене, оплата не підтверджена | Зачекати |
| `🧾 Оплата на перевірці` | Клієнт натиснув `Я оплатив(ла)` | Перевірити надходження і підтвердити |
| `✅ Оплачено` | Оплата підтверджена | Відправляти |
| `❌ Скасовано` | Замовлення скасоване | — |
| `⌛ Прострочено` | Оплата не завершена вчасно | — |

### Статуси: накладений платіж

| Статус | Що означає | Ваша дія |
|---|---|---|
| `📦 Очікує відправки` | Замовлення створене, готове до відправлення | Створити ТТН і відправити |
| `🚚 Відправлено` | Посилку відправлено | Чекати на отримання |
| `📍 Очікує отримання` | Посилка у відділенні | Чекати |
| `✅ Оплачено` | Клієнт отримав і оплатив | Закрити |
| `❌ Скасовано` | Не забране або повернуте | — |

### Дії в картці замовлення

| Кнопка | Коли зʼявляється |
|---|---|
| `✅ Підтвердити оплату` | Коли потрібна ручна перевірка |
| `🚚 Створити ТТН` | Якщо налаштована Нова пошта |
| `🚚 Відправлено` | Для накладеного платежу |
| `❌ Скасувати` | Для скасування замовлення |
| `🔎 Відстежити` | Після створення ТТН — веде на трекінг Нової пошти |

### Робоча звичка

Мінімум **двічі на день** перевіряйте два фільтри:

- `⏳ Очікують`
- `🧾 На перевірці`

Це найважливіше на старті магазину. Замовлення в статусі «на перевірці» — це людина, яка вже віддала гроші й чекає на підтвердження. Кожна година мовчання тут коштує вам довіри.

## Оплати

Платформа підтримує пʼять способів:

| Спосіб | Тип |
|---|---|
| `LiqPay` | Онлайн-еквайринг |
| `plata by mono` (Monobank Merchant) | Онлайн-еквайринг |
| `Оплата за посиланням` | Онлайн |
| `Оплата за реквізитами` | Переказ на рахунок |
| `Накладений платіж` | Оплата при отриманні |

Усе налаштовується в одному місці: `Керування` → `Налаштування` → `Оплати` → картка **Оплати клієнтів**.

Інтерфейс розділений на окремі блоки по кожному способу, щоб не плутати чекбокси й поля. Після заповнення тисніть `Зберегти оплату`.

### Як це бачить покупець

- `💳 Оплатити онлайн через LiqPay` — Apple Pay, Google Pay або картка;
- `💳 Оплатити онлайн через Monobank` — насправді це еквайринг `plata by mono`, картка будь-якого банку, Apple Pay або Google Pay;
- `🏦 Банківські реквізити` — позначені бейджем `IBAN`;
- `📦 Накладений платіж` — оплата при отриманні;
- кнопка `Я оплатив(ла)` — для способів, де потрібна ваша ручна перевірка.

Для LiqPay і Monobank після успішної оплати замовлення підтверджується автоматично — вам нічого робити не треба.

## Доставка

Нова пошта налаштовується в `Керування` → `Налаштування` → `Доставка` → картка **Нова пошта**.

Порядок має значення:

1. Вставте `API ключ` і натисніть `Зберегти API ключ`.
2. Знайдіть `Місто відправника` через кнопку `Знайти місто` і виберіть зі списку.
3. Знайдіть `Точка відправлення` через `Знайти точку відправлення` і виберіть зі списку.
4. Заповніть `ПІБ відправника`.
5. Заповніть `Телефон відправника`.
6. Натисніть `Зберегти доставку`.

!!! warning "Не вводьте місто і відділення вручну"
    Ці значення мають вибиратися зі списків пошуку. Просто набраний текст не підійде — система не отримає внутрішні ідентифікатори Нової пошти, і ТТН не створиться.

## Налаштування

Вкладка `Налаштування` всередині `Керування` має вісім секцій.

### `Підписка`

Картка **Підписка магазину**. Тут ви бачите поточний тариф і період, а також керуєте доступністю магазину:

- `Застосувати режим` — застосувати обраний режим доступу;
- `Оплатити підписку`;
- `Відкрити активний рахунок`;
- історія платежів і договори.

Режими доступу магазину:

| Режим | Що відбувається |
|---|---|
| `За статусом підписки` | Доступ визначається поточною підпискою — режим за замовчуванням |
| `Працює у звичайному режимі` | Магазин примусово активний |
| `Пауза checkout` | Каталог видно, але нові замовлення не оформлюються |
| `Магазин приховано для клієнтів` | Вітрина тимчасово недоступна |

!!! tip "Коли стане в пригоді «Пауза checkout»"
    Поїхали у відпустку або закінчився товар — поставте паузу замість того, щоб ховати магазин повністю. Покупці далі бачать асортимент і повертаються, коли ви знімете паузу.

### `Оплати`

Картка **Оплати клієнтів**. Розібрано вище і на сторінці [Оплати](payments.md).

### `Покупці`

Дві картки:

- **Нагадування про кошик** — повернення покупців, які не дійшли до оплати;
- **Кабінет покупця** — особистий розділ клієнта з історією замовлень.

### `Модулі`

Картка **Модулі магазину**. Тут вмикаються і вимикаються доступні модулі відповідно до вашого тарифу. Якщо якоїсь вкладки не видно — почніть перевірку звідси.

### `Доставка`

Картка **Нова пошта**. Описано вище.

### `Вигляд`

Картка **Зовнішній вигляд магазину**, кнопка входу в редактор — `Редагувати вигляд`.

Доступні параметри: тема, акцентний колір, шрифт, скруглення, щільність, контраст інтерфейсу, глибина тіней, стиль карток, стиль кнопок, логотип, банер.

!!! tip "Не перестарайтеся"
    Найсильніше на сприйняття магазину впливають дві речі: якісні фото товарів і зрозумілий логотип. Ексклюзивні шрифти й тіні цього не замінять.

### `Команда`

Картка **Адміни магазину**. Щоб додати нового адміністратора, введіть його **числовий Telegram ID** у поле і натисніть `Додати`.

Щоб дізнатися ID, попросіть людину надіслати боту команду `/myid`.

### `Контент`

Дві картки:

- **Тексти магазину** — привітання, описи, службові повідомлення;
- **Кнопки та назви** — підписи кнопок і розділів.

## Модулі зростання

Ці інструменти працюють тоді, коли базовий магазин уже стабільний. Раніше вмикати їх немає сенсу.

### Промокоди

Вкладка `Промокоди`. Можна створювати коди, задавати тип знижки, мінімальну суму, обмежувати кількість використань, вибирати сегмент аудиторії та місце показу.

### Клієнти

Вкладка `Клієнти`: база клієнтів, сегменти, правила сегментів, LTV та підсумкові показники.

### Кампанії

Вкладка `Кампанії` — розсилки по сегментах. У боті розділ `📣 Кампанії` зʼявляється тільки тоді, коли модуль дозволений тарифом і увімкнений.

### Аналітика

У боті — `📊 Статистика —✨Pro` з експортом у `📄 CSV` та `📊 Excel (.xlsx)`.

У WebApp — вкладка `Аналітика` з перемиканням періодів: `Сьогодні`, `7 днів`, `30 днів`, `Весь час`.

### Крос-продажі

Вкладка `Крос-продажі` — рекомендації супутніх товарів. Стає корисною після того, як накопичиться достатньо замовлень: без даних рекомендувати нема з чого.

## Часті ситуації

??? question "Немає доступу до адмінки"
    Повідомлення «Немає доступу» означає, що вашого Telegram ID немає в списку адміністраторів магазину.

    1. Переконайтеся, що ви під правильним Telegram-акаунтом.
    2. Надішліть боту `/myid`.
    3. Скопіюйте **числовий** ID — не `@username`, а саме число.
    4. Передайте його власнику магазину або платформному адміну.
    5. Він додасть вас у `Налаштування` → `Команда` → **Адміни магазину**.

??? question "Замовлення не рухаються далі"
    Перевірте по черзі:

    - чи клієнт справді оплатив;
    - чи не зависло замовлення в статусі `🧾 Оплата на перевірці` — його потрібно підтвердити вручну;
    - чи ви не пропустили фільтри `⏳ Очікують` і `🧾 На перевірці`.

    Найчастіша причина — замовлення чекає саме на вашу дію.

??? question "Товар не купується"
    Перевірте:

    - чи товар активний (галочка `Активний у каталозі`);
    - чи є в нього фото;
    - чи коректна ціна;
    - чи він у правильній категорії;
    - чи не заблокований checkout через відсутність онлайн-оплати для товару в режимі `Без ліміту залишку`.

    Останній пункт — найпоширеніша прихована причина.

??? question "Не створюється ТТН"
    Для створення ТТН одночасно мають виконуватися пʼять умов:

    1. увімкнений модуль Нової пошти;
    2. збережений API ключ;
    3. заповнені дані відправника — ПІБ і телефон;
    4. вибрані місто і точка відправлення **зі списків пошуку**;
    5. у самому замовленні є дані отримувача з коректним містом і відділенням.

    Найчастіше проблема в пунктах 4 і 5.

??? question "Зникла вкладка або модуль"
    Дві причини, в такому порядку перевірки:

    1. модуль вимкнений — подивіться `Налаштування` → `Модулі`;
    2. поточний тариф його не дозволяє — подивіться `Налаштування` → `Підписка`.

??? question "Клієнти пишуть, що магазин не відкривається"
    Спершу перевірте `Налаштування` → `Підписка` → режим доступу. Якщо стоїть `Магазин приховано для клієнтів` або `Пауза checkout` — справа в цьому.

    Якщо режим звичайний, а магазин усе одно не відкривається — це вже питання до платформного адміністратора.

## Що робити далі

Коли базовий магазин працює стабільно:

1. **Вирівняйте основу.** Каталог, оплати, доставка — щоб не було винятків і ручних милиць.
2. **Наведіть порядок у текстах і вигляді.** Це те, за чим вас запамʼятовують.
3. **Тільки після цього вмикайте зростання.** Промокоди, кампанії, аналітику, крос-продажі.
4. **Регулярно перевіряйте підписку і режим доступу**, щоб магазин не зупинився в найгірший момент.

!!! tip "Головне правило"
    Не намагайтеся ввімкнути все одразу. Спочатку зробіть стабільною операційну основу: каталог, оформлення, оплата, замовлення, доставка. Магазин, у якому працює це, продає більше за магазин з десятком увімкнених модулів і зламаним checkout.
